# 流程引擎配置（明清官制版）

## 概述

三审六部流程引擎由 **11个节点** 串联而成，分四层：**触发层 → 执行层（六部）→ 审核层（三审）→ 输出层**，外加异步监控贯穿全程。

核心规则：
1. **串行不可跳** — 节点必须按顺序流转，不可跳过
2. **审核不可逆** — 一审/二审/三审裁定结果一经发出不可撤回
3. **红线即终止** — 红线触发立即终止，无例外
4. **超时不阻塞** — 执行层超时标记跳过，审核层超时视为驳回

## 节点详规

### N01：点将台（流程启动）

| 属性 | 值 |
|------|-----|
| 类型 | 触发层·系统节点 |
| 超时 | 0（瞬时执行） |
| 触发条件 | 定时 09:25 / 东家输入商号代码或名称 / 复盘指令 |

**输入：** 无
**输出：** 任务令牌 + 启动参数

**输出模板：**
```json
{
  "message_type": "N01_START",
  "task_id": "任务唯一UUID",
  "timestamp": "ISO时间戳",
  "payload": {
    "mode": "晨间点将 / 东家钦点 / 复盘修史 / 五维选贤",
    "target": {
      "codes": ["商号代码列表"],

      "version": "三审六部.v1.0",
      "mode": "ancient"
    }
  }
}
```

**异常处理：** 无参数 → 报错终止，通报东家

### N06：户部调拨（仓位规划）

| 属性 | 值 |
|------|-----|
| 类型 | 执行层·仓位 |
| 执行者 | Agent 04 户部主事（从五品·主事） |
| 超时 | 60s |
| 超时处理 | 标记"调度方案延迟"，使用默认半凯利保守方案 |

**输入：** N05 判词 + N02 密报
**输出：** 银两调度方案

**计算方法：**
1. 基础调度 = 总银两 × 风险乘数（低20-30%/中10-20%/高5-10%）
2. 凯利比例 f* = (p × b - q) / b
3. 实际调度 = 基础调度 × 凯利比例 × 0.5（半凯利保守）
4. 最终调度 = min(实际调度, 总银两 × 30%)
5. 分批计划：首仓50%、加仓30%、补仓20%（各有触发条件）

**输出模板：**
```json
{
  "message_type": "N06_银两调度方案",
  "task_id": "任务UUID",
  "from_agent": "agent_04",
  "to_agent": "agent_08",
  "timestamp": "ISO时间戳",
  "payload": {
    "target": { "code": "商号代码", "name": "商号名称" },
    "调度方案": {
      "总银两": 0,
      "风险乘数": "X%（低/中/高风险）",
      "基础调度": "XX两(X%)",
      "凯利比例": "f* = (p×b-q)/b = X%",
      "实际调度": "XX两(半凯利)",
      "分批计划": {
        "首仓": {"比例": "50%", "银两": 0, "触发": "立即入局"},
```

## 数据流转规范

1. 所有节点必须使用标准JSON文书格式
2. 每个文书必须包含 `task_id`（贯穿全流程的任务唯一标识）
3. 所有时间使用ISO格式
4. 金额单位统一为"两"
5. 百分比统一保留两位小数
6. 驳回文书必须包含具体原因
